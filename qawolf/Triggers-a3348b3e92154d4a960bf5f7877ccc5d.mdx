title: "Triggers"
---

<Note>
Triggers can only be edited by a QA Wolf representative. However, customers may benefit from a basic understanding of this concept, as it participates in the CI integration flow, especially in the [Deploy Success Webhook](/qawolf/Deploy-Success-Webhook-dd72e46ceb7f451dae4e9ef06f64a2cc).
</Note>

There are two kinds of triggers:

- **Scheduled triggers** create runs on a configurable period (e.g., daily).
- **Deployment triggers** create runs based on events in the CICD pipeline.

Triggers are entities associated with environments, which can be thought of as “conditional runs executions.”

The Trigger modal allows a QA Wolf representative to set up the matching conditions for the [Deploy Success Webhook](/qawolf/Deploy-Success-Webhook-dd72e46ceb7f451dae4e9ef06f64a2cc) `POST` request to spawn a new run. It also supports selecting a subset of the workflows available in this environment by matching tags.
