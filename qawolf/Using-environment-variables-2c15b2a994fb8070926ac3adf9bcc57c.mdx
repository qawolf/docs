## About environment variables

In the QA Wolf platform, environment variables are encrypted constants scoped to a specific environment.

You can use the same variable across environments by reusing the same name in each environment and setting the appropriate value for that environment (for example, BASE_URL in Staging vs Production). QA Wolf doesn't enforce cross-environment consistency—this pattern relies on naming conventions.

## How to call an env variable

Call an environment variable in your code by using the `process.env` object.

In this example, we use the standard Playwright `page.goto` function to open the location defined in the `BASE_URL` environment variable.

## Update environment variables from code

Use `saveEnvironmentVariable(name, value)` from `@qawolf/testkit` when a flow needs to persist a string value back to the current QA Wolf environment. The helper also updates `process.env[name]` for the current run.

Use `reloadEnvironmentVariables()` to fetch the latest environment variables for the current environment and copy string values into `process.env`.

```typescript
import {
  reloadEnvironmentVariables,
  saveEnvironmentVariable,
} from "@qawolf/testkit";

await saveEnvironmentVariable("SESSION_TOKEN", token);
await reloadEnvironmentVariables();

await page.goto(process.env.BASE_URL);
```

These helpers are available in QA Wolf runner environments. For exact signatures and error behavior, see the [Testkit Core Reference](/qawolf/libraries/testkit/api-reference/core#environment-variables).
