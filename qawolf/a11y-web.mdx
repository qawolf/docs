## Overview

For web accessibility testing, QA Wolf supports two practical approaches:

- **Axe-core** — injects a rules engine into the page and returns WCAG violations grouped by severity. Best for CI-style checks and release gating.
- **Lighthouse** — generates an accessibility score and shareable report artifact. Best when you need a formal audit report for stakeholders.

Both run via **Playwright** and can be added to any existing QA Wolf test.

---

## Axe-Core Scan

The most common approach. Axe-core is injected into the page and run in the browser context, returning violations at four severity levels: `critical`, `serious`, `moderate`, and `minor`.

```ts
// 1) Navigate
await page.goto(process.env.TARGET_URL!);

// 2) Let the page settle
await page.waitForLoadState("networkidle").catch(() => {});

// 3) Inject axe-core
await page.addScriptTag({
  url: "https://unpkg.com/axe-core@4.8.2/axe.min.js",
});

// 4) Run the audit in the browser context
const violations = await page.evaluate(async () => {
  // @ts-ignore
  const { violations } = await window.axe.run();
  return violations;
});

// 5) Summarize results by severity
const critical = violations.filter(v => v.impact === "critical");
const serious  = violations.filter(v => v.impact === "serious");
const moderate = violations.filter(v => v.impact === "moderate");
const minor    = violations.filter(v => v.impact === "minor");

console.log("A11y results:", {
  critical: critical.length,
  serious:  serious.length,
  moderate: moderate.length,
  minor:    minor.length,
});

// 6) Optional: gate the test on severity thresholds
if (critical.length > 0 || serious.length > 0) {
  throw new Error(
    `Accessibility gate failed: ${critical.length} critical, ${serious.length} serious`
  );
}
```

<Tip>
  The gate above fails on `critical` and `serious` violations. Adjust the threshold to match your policy — some teams also gate on `moderate`, particularly in regulated industries.
</Tip>

## Lighthouse Accessibility Report

If the goal is a formal, shareable artifact with an accessibility score, Lighthouse is the better fit. QA Wolf uses `playwright-lighthouse` to run Lighthouse within a Playwright test and can generate HTML, JSON, or PDF reports.

See the [Lighthouse Accessibility reference page](#) for required dependencies and imports, setup instructions, report generation, and known limitations.

<Warning>
  Lighthouse scores accessibility against its own model, which does not map 1:1 to WCAG conformance levels. Use it as a directional score and audit artifact — not as a hard compliance gate.
</Warning>

## Choosing the Right Approach

|  | Axe-core | Lighthouse |
| --- | --- | --- |
| **Best for** | CI checks, violation counts, release gating | Scores, formal reports, stakeholder sharing |
| **Output** | Violation list by severity | Accessibility score \+ full report |
| **Use as a gate** | Yes — throw on critical / serious | Not recommended |
| **Report artifact** | No (console / logs) | Yes — HTML, JSON, PDF |

<Note>
  These two approaches complement each other. Axe-core is precise and gateable; Lighthouse is broad and reportable. For the most complete picture, use both.
</Note>
