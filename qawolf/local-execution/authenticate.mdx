Before the CLI can pull flows from your workspace or run flows that depend on environment variables, it needs a credential. Sign in through your browser for local development, or pass an API key through an environment variable for CI.

## Install the CLI

The CLI ships in two forms: an npm package and a precompiled standalone binary.

### Install with npm

<Check>
  Node.js 22.12 or later is required.
</Check>

```bash
npm install -g @qawolf/cli
```

### Install a precompiled binary

Download the binary for your platform from [GitHub Releases](https://github.com/qawolf/cli/releases). Builds are published for Linux (x64 and arm64), macOS (Apple Silicon and Intel), and Windows x64. The binary has no Node.js runtime dependency. Extract the archive, then move the binary into a directory on your `PATH`.

### Verify

```bash
qawolf --version
```

## Log in for local development

<Steps>
  <Step>
    Run the login command:

    ```bash
    qawolf auth login
    ```
  </Step>
  <Step>
    Choose **Browser**. The CLI shows a short code and opens the verification page. Confirm the code in your browser. If the CLI cannot open a browser, it prints the URL for you to open.
  </Step>
  <Step>
    If your account can access more than one organization or workspace, choose the one to work in. The CLI asks only when there is more than one.
  </Step>
  <Step>
    Confirm the connection:

    ```bash
    qawolf auth whoami
    ```

    The output shows your email, your organization, the active workspace, and where the credential was loaded from.
  </Step>
</Steps>

The CLI stores the session in your system keychain and refreshes it before it expires. When a keychain is not available, the CLI falls back to a local config file in your user profile directory.

### Log in with an API key

To use an API key instead, choose **API key** at the prompt and paste a key generated in your QA Wolf workspace under **Workspace settings → API keys**. The CLI validates the key against the platform and stores it the same way. Use this path if your QA Wolf deployment does not offer browser sign-in.

An API key and a browser session don't grant the same access: an API key carries workspace scope that a browser session does not. When both are stored, the CLI uses the API key.

## Switch workspaces

A browser session can access several workspaces. To change the one the CLI works in without signing in again:

```bash
qawolf auth switch
```

To choose without a prompt, set `QAWOLF_WORKSPACE` to a workspace name, slug, or ID. When the same workspace name exists in more than one organization, also set `QAWOLF_ORGANIZATION`. This applies to browser sessions only; an API key already carries its workspace.

## Authenticate in CI

CI environments cannot prompt for input. Set the `QAWOLF_API_KEY` environment variable instead:

```bash
export QAWOLF_API_KEY=<your-api-key>
qawolf flows pull --env <env_id>
```

The CLI reads credentials in this order: `QAWOLF_API_KEY`, then an API key stored by `qawolf auth login`, then a browser session. The same machine can switch between accounts by setting or unsetting the variable.

## Log out

```bash
qawolf auth logout
```

`qawolf auth logout` removes the browser session and any API key stored by `qawolf auth login` — see [`auth logout`](/qawolf/libraries/cli/api-reference/commands#auth-logout) for exact behavior. To remove a `QAWOLF_API_KEY` credential, unset the variable in your shell instead.

## Switch the deployment host

By default the CLI talks to `https://app.qawolf.com`. Override this with `QAWOLF_HOST_URL` if your workspace uses a different host:

```bash
export QAWOLF_HOST_URL=https://qawolf.example.com
```

See the [Environment variables reference](/qawolf/libraries/cli/api-reference/environment-variables) for the full list of variables the CLI reads.
