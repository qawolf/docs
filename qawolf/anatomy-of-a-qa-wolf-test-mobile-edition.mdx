If Automation AI generated a flow for you and you want to understand what it produced, this page explains each part.

If your team has written Playwright or Appium tests before, QA Wolf tests will look familiar. The selectors, interactions, and assertions work the same way. What's different is the wrapper around them.

## The import statement

<CodeGroup>

```javascript Web
import { flow, expect } from "@qawolf/flows/web";
```

```javascript iOS
import { flow, device } from "@qawolf/flows/ios";
```

```javascript Android
import { flow, device, expect } from "@qawolf/flows/android";
```

</CodeGroup>

`flow` is the outer container for every QA Wolf test. Import it from the package that matches your target platform. On web and Android, also import `expect` from the same package — this ensures assertions are wired into QA Wolf's reporting. On iOS, import `device` to access platform utilities like network simulation, media injection, and more.

<Warning>
  On web and Android, importing `expect` from `@playwright/test` instead of the flows package will cause assertions to bypass QA Wolf's reporting. Always import from the flows package.
</Warning>

## The flow wrapper

`flow()` takes three arguments: a name, an options object, and an asynchronous function containing the test logic.

<CodeGroup>

```javascript Web
export default flow(
  "Test Name",
  { target: "Web - Chrome", launch: true },
  async ({ page, test }) => {
    // test steps go here
  },
);
```

```javascript iOS
export default flow(
  "Test Name",
  { target: "iOS - iPhone 15 (iOS 18)", launch: { bundleId: "com.example.app" } },
  async ({ driver, test }) => {
    // test steps go here
  },
);
```

```javascript Android
export default flow(
  "Test Name",
  { target: "Android - Pixel 9 (Android 15)", launch: { appPackage: "com.example.android" } },
  async ({ driver, test }) => {
    // test steps go here
  },
);
```

</CodeGroup>

**Name** — what this test is called in your results, bug reports, and QA Wolf dashboard. Make it descriptive enough that a failing test name tells you where to look.

**Options object** — contains `target` (the device and environment the test runs on) and `launch` (how the session starts). Set `launch: true` to start with defaults, or pass a typed options object to configure the session. The system resolves the target at runtime into a running session. No additional configuration required.

**Test function** — the `async` function containing your test logic. It receives `test` for defining named steps, plus `page` (web) or `driver` (mobile) injected directly by the runtime.

<Note>
  In vanilla Playwright, you configure browsers in `playwright.config.js`. In vanilla Appium, you configure the target device through desired capabilities. In QA Wolf, the `target` string and `launch` options handle both. The infrastructure resolves it at runtime.
</Note>

## Environment variables

Use `process.env.VAR_NAME` to reference environment variables in your flow. They are typically used in the Arrange section.

<CodeGroup>

```javascript Web
await page.goto(process.env.BASE_URL);
```

```javascript iOS
export default flow(
  "Test Name",
  {
    target: "iOS - iPhone 15 (iOS 18)",
    launch: {
      app: { env: "APP_STAGING" },
      autoAcceptAlerts: true,
    },
  },
  async ({ driver, test }) => {
    // driver is ready to use
  },
);
```

```javascript Android
export default flow(
  "Test Name",
  {
    target: "Android - Pixel 9 (Android 15)",
    launch: { app: { env: "APP_STAGING" } },
  },
  async ({ driver, test }) => {
    // driver is ready to use
  },
);
```

</CodeGroup>

To set environment variables for your flows, see [Environment setup](/qawolf/Environment-settings-2cd5b2a994fb8014ba8bd7aa25f3ed0f#create-and-manage-environment-variables).

## The AAA framework

QA Wolf generates tests in the Arrange, Act, Assert (AAA) format.

**Arrange** sets up the state and launches the session.

**Act** performs the interaction being tested.

**Assert** verifies the expected outcome.

<CodeGroup>

```javascript Web
await test("Complete checkout", async () => {
  //--------------------------------
  // Arrange:
  //--------------------------------
  await page.goto("https://www.example.com/checkout");

  //--------------------------------
  // Act:
  //--------------------------------
  await page.fill("[data-testid='email']", "test@example.com");
  await page.click("[data-testid='submit']");

  //--------------------------------
  // Assert:
  //--------------------------------
  await expect(page).toHaveURL("https://www.example.com/confirmation");
});
```

```javascript iOS
await test("Log in", async () => {
  //--------------------------------
  // Arrange:
  //--------------------------------
  await driver.$("~username").waitForDisplayed();

  //--------------------------------
  // Act:
  //--------------------------------
  await driver.$("~username").setValue("test@example.com");
  await driver.$("~password").setValue("password");
  await driver.$("~submit").click();

  //--------------------------------
  // Assert:
  //--------------------------------
  await driver.$("~dashboard").waitForDisplayed();
});
```

```javascript Android highlight={5-6}
await test("Log in", async () => {
  //--------------------------------
  // Arrange:
  //--------------------------------
  await driver.$("~username").waitForDisplayed();

  //--------------------------------
  // Act:
  //--------------------------------
  await driver.$("~username").setValue("test@example.com");
  await driver.$("~password").setValue("password");
  await driver.$("~submit").click();

  //--------------------------------
  // Assert:
  //--------------------------------
  await driver.$("~dashboard").waitForDisplayed();
});
```

</CodeGroup>
