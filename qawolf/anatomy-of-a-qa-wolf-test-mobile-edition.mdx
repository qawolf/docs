If Automation AI generated a flow for you and you want to understand what it produced, this page explains each part. If your team has written Playwright or Appium tests before, QA Wolf flows will look familiar. The selectors, interactions, and assertions work the same way. What's different is the wrapper around them.

## The import statement

Import `flow` and `expect` from the package that matches your target platform.

<CodeGroup>
```typescript Web
import { flow, expect } from "@qawolf/flows/web";
```
```typescript iOS
import { flow, expect } from "@qawolf/flows/ios";
```
```typescript Android
import { flow, expect } from "@qawolf/flows/android";
```
</CodeGroup>

Always import `expect` from the flows package — not from `@playwright/test`. Importing from `@playwright/test` will cause assertions to bypass QA Wolf's reporting.

## The flow wrapper

`flow()` takes three arguments: a name, a target, and an async callback containing the test logic.

```typescript
export default flow(
  "Name shown in QA Wolf",
  { target: "Web - Chrome", launch: true },
  async ({ page }) => {
    // test steps go here
  },
);
```

**Name** — what this flow is called in your results, bug reports, and QA Wolf dashboard. Make it descriptive enough that a failing flow name tells you where to look.

**Target** — the device and environment the flow runs on. The format is `"Platform - Device (OS Version)"` for mobile and `"Web - Browser"` for web. The infrastructure resolves it at runtime — no additional configuration required.

**Callback** — the `async` function containing your test logic. What it receives depends on the launch style (see below).

## Launch styles

### `launch: true` — recommended

Pass `{ target, launch: true }` and QA Wolf starts the session before your callback runs. The callback receives the platform object directly.

<CodeGroup>
```typescript Web
export default flow(
  "Sign in",
  { target: "Web - Chrome", launch: true },
  async ({ page }) => {
    await page.goto(process.env.BASE_URL);
  },
);
```
```typescript iOS
export default flow(
  "Sign in",
  { target: "iOS - iPhone 15 (18)", launch: true },
  async ({ driver }) => {
    // driver is ready to use
  },
);
```
```typescript Android
export default flow(
  "Sign in",
  { target: "Android - Pixel 7 (14)", launch: true },
  async ({ driver }) => {
    // driver is ready to use
  },
);
```
</CodeGroup>

The callback receives the launched object for that platform:

| Entry point | Callback receives |
|---|---|
| `@qawolf/flows/web` | `page`, `context`, optional `browser` |
| `@qawolf/flows/android` | `driver` |
| `@qawolf/flows/ios` | `driver` |

When startup needs options, pass an options object to `launch` instead of `true`:

```typescript
export default flow(
  "Sign in with saved profile",
  {
    target: "Web - Chrome",
    launch: {
      browserContext: "persistent",
      userDataDir: "/tmp/qawolf-profile",
    },
  },
  async ({ page }) => {
    await page.goto(process.env.BASE_URL);
  },
);
```

### Manual launch — advanced flows only

Pass the target directly and call `launch()` inside the callback when startup depends on runtime logic.

```typescript
import { flow, launch } from "@qawolf/flows/web";

export default flow("Sign in", "Web - Chrome", async () => {
  const useSavedProfile = process.env.USE_SAVED_PROFILE === "true";

  const launchResult = await launch(
    useSavedProfile
      ? { browserContext: "persistent", userDataDir: "/tmp/qawolf-profile" }
      : undefined,
  );
  if (!("context" in launchResult)) throw new Error("Expected browser launch");

  const page =
    "page" in launchResult
      ? launchResult.page
      : await launchResult.context.newPage();

  await page.goto(process.env.BASE_URL);
});
```

Use manual launch only when you need to branch on runtime state before launching, delay launch until after setup steps, or combine startup with callback-only data.

## Environment variables

Reference environment variables with `process.env.VAR_NAME`. They are typically used in the Arrange section before any interactions begin.

```typescript
await page.goto(process.env.BASE_URL);
```

To set environment variables for your flows, see [Environment setup](/qawolf/Environment-settings-2cd5b2a994fb8014ba8bd7aa25f3ed0f#create-and-manage-environment-variables).

## The AAA framework

QA Wolf flows follow the Arrange, Act, Assert (AAA) format.

**Arrange** sets up state before the interaction.  
**Act** performs the interaction being tested.  
**Assert** verifies the expected outcome.

<CodeGroup>
```typescript Web
export default flow(
  "Complete checkout",
  { target: "Web - Chrome", launch: true },
  async ({ page }) => {
    //--------------------------------
    // Arrange:
    //--------------------------------
    await page.goto(process.env.BASE_URL);

    //--------------------------------
    // Act:
    //--------------------------------
    await page.fill("[data-testid='email']", "test@example.com");
    await page.click("[data-testid='submit']");

    //--------------------------------
    // Assert:
    //--------------------------------
    await expect(page).toHaveURL(`${process.env.BASE_URL}/confirmation`);
  },
);
```
```typescript iOS
export default flow(
  "Complete checkout",
  { target: "iOS - iPhone 15 (18)", launch: true },
  async ({ driver }) => {
    //--------------------------------
    // Arrange:
    //--------------------------------

    //--------------------------------
    // Act:
    //--------------------------------

    //--------------------------------
    // Assert:
    //--------------------------------
  },
);
```
```typescript Android
export default flow(
  "Complete checkout",
  { target: "Android - Pixel 7 (14)", launch: true },
  async ({ driver }) => {
    //--------------------------------
    // Arrange:
    //--------------------------------

    //--------------------------------
    // Act:
    //--------------------------------

    //--------------------------------
    // Assert:
    //--------------------------------
  },
);
```
