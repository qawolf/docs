Smart Smoke Suites (also called Adaptive Flow Selection) automatically runs the most relevant subset of your test suite against every PR preview deployment, instead of running the full suite on every change. Tester, QA Wolf's in-platform AI, reads each PR's title and description, infers the area of risk, and runs a targeted set of flows against your preview environment.

The goal: keep PR testing lightweight and fast by default, while still surfacing deeper signal on higher-risk changes, without engineers having to think about which tests to trigger.

<Note>
  Smart Smoke Suites is currently in alpha. Early customers running it in production work closely with QA Wolf to validate the experience and tune selection quality.
</Note>

## Why it matters

- **Faster signal on every deploy.** Targeted runs finish faster than full-suite runs, so engineers see results sooner in the review cycle.
- **Coverage on changes that previously had none.** PRs that wouldn't have triggered a manual test now get automatic, change-specific coverage.
- **No new test authoring required.** Selection works against the flows already in your suite.
- **Lower cost-to-coverage ratio.** Fewer flows run per PR, but change-specific risk is still caught early.

## How it works

When a PR preview environment deploys to a configured trigger:

1. Tester reads the PR title and description from GitHub.
2. It maps the described change against your existing flow library, weighting by feature area, surface, and historical relevance.
3. A targeted run starts against the preview environment using only the selected flows.
4. Results post back through your normal QA Wolf notifications.

Selection draws from your existing tests — no new flows are written, and nothing in your suite is hidden or removed.

<Tip>
  The richer the PR description, the more precise the selection. You don't need to change how you write PRs, but well-scoped titles and descriptions yield the sharpest results.
</Tip>

## Configuration options

Smart Smoke Suites is designed to layer onto your existing setup rather than replace it. A few common patterns:

- **Adaptive selection only.** Tester picks the flow set for every PR. Simplest setup.
- **Fixed baseline + adaptive layer.** Define a core set of flows that always runs on every PR, with adaptive selection adding relevant flows on top.
- **Tag-based split.** Run adaptive selection on one tag (e.g., front-end PRs) while keeping another tag on a fixed list — useful when different surfaces need different behavior.
- **Branch rules for high-risk merges.** Use branch-name rules to keep specific branches (e.g., `release-candidate-*`) on the full smoke suite, while everything else runs adaptive selection.
- **Manual full-suite override.** A "run all flows" option is available on the trigger, so you can force a full run on a higher-stakes PR without changing the default behavior.

## Requirements

To enable Smart Smoke Suites, the following need to be in place:

- The **QA Wolf GitHub App** installed in the target repository.
- **Stable preview environments** for PRs, with deployments registered as GitHub Deployments or notified to QA Wolf via the deployment notification action.
- A **pool of stable flows** in your existing suite for Tester to select from.

These are the same prerequisites as standard PR testing — no additional infrastructure required.

## Setup

<Steps>
  <Step title="Install the QA Wolf GitHub App">
    Install the app in the target repository.
  </Step>
  <Step title="Configure preview environment notifications">
    Register deployments as GitHub Deployments, or notify QA Wolf on new deployments with the deployment notification action.
  </Step>
  <Step title="Enable Smart Smoke Suites">
    Turn on the feature for the relevant trigger — a single checkbox in the trigger configuration.
  </Step>
  <Step title="Configure baseline flows or branch rules (optional)">
    Layer on a fixed baseline or branch-name rule based on the pattern that fits your workflow.
  </Step>
</Steps>

Once configured, every new preview deployment automatically starts a targeted test run. Enabling and disabling is a single toggle on the trigger, so you can turn it off instantly to revert to standard PR testing.

## Things to know

- **Alpha feature.** See the note above — early customers work closely with QA Wolf to tune selection quality.
- **Investigation on request.** Adaptive PR runs are not actively investigated by the QA Wolf team by default. If you'd like a specific PR run investigated, flag it through your usual support channel.

## FAQ

### How does Tester decide which flows to run?

Selection is driven by Tester's read of the PR title and description, mapped against your existing flow library. The clearer the PR context, the sharper the selection.

### Can we add specific tests to always run on PRs?

Yes. Configure a fixed baseline of flows that always runs, with adaptive selection layered on top.

### Can we run the full suite on a specific PR when we want to?

Yes. A "run all flows" option is available on the trigger so you can force a full run on higher-stakes PRs.

### Will high-risk branches (release candidates, hotfixes) still get full coverage?

Yes. Branch-name rules let you keep specific branches on the full smoke suite while everything else runs adaptive selection.

### Does this replace our scheduled full-suite runs?

No. Smart Smoke Suites runs on PR deployments and layers onto your existing setup. Scheduled runs continue unchanged.

### Does this require us to write new tests?

No. Selection works against the flows already in your suite.

### How is this billed?

Adaptive runs use a targeted slice of your existing flow capacity rather than additional capacity. Your CSM can confirm specifics for your contract.
