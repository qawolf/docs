# Write A CLI Flow

Use `@qawolf/flows/cli` when the flow does not need a browser, Android device,
or iOS device.

```ts
import { flow } from "@qawolf/flows/cli";
import { readFile } from "node:fs/promises";

export default flow("Read build metadata", "Basic", async () => {
  const metadata = await readFile("build-metadata.json", "utf8");

  console.log(JSON.parse(metadata));
});
```

## Use The `Basic` Target

CLI flows currently support one target.

<CodeGroup>

```ts String target
export default flow("CLI task", "Basic", async ({ workflowInputs }) => {
  console.log(workflowInputs);
});
```

```ts Object target
export default flow(
  "CLI task",
  { target: "Basic" },
  async ({ workflowInputs }) => {
    console.log(workflowInputs);
  },
);
```

</CodeGroup>

## Use Node APIs Directly

CLI flows run in Node, so prefer the Node standard library for ordinary file,
process, and network work.

```ts
import { writeFile } from "node:fs/promises";

export default flow("Write report", "Basic", async () => {
  await writeFile("report.json", JSON.stringify({ status: "ok" }));
});
```

Use CLI flows for setup, teardown, notifications, and other non-UI work. Reach
for runner-provided dependencies only when you specifically need QA Wolf runtime
services such as workflow inputs or outputs.
