# Get Started

`@qawolf/flows` is the authoring surface for QA Wolf flows.

Use the platform-specific entry point for authoring:

- `@qawolf/flows/web`
- `@qawolf/flows/android`
- `@qawolf/flows/ios`
- `@qawolf/flows/cli`

Use the top-level `@qawolf/flows` package for cross-platform helpers such as
`platform.target`, `configureTarget(...)`, `getCurrentScope()`, and
`resetTarget()`.

## What This Package Covers

Each platform package follows the same high-level model:

- `flow(...)` for the common authoring path
- `launch(...)` for more explicit runtime control inside a running flow
- `device` for advanced mobile-only device operations

`@qawolf/flows/cli` is the exception to the full platform model:

- it exposes `flow(...)`
- it uses the `"Basic"` target
- it does not expose `launch(...)`
- it does not expose `device`

## Smallest Working Example

The fastest way to start is a launch-enabled web flow:

```ts
import { flow } from "@qawolf/flows/web";

export default flow(
  "Sign in",
  { target: "Web - Chrome", launch: true },
  async ({ page }) => {
    await page.goto("https://example.com");
  },
);
```

Use this shape when you want the callback to receive launched browser session
objects directly.

## The Two Ways To Start A Flow Session

### 1. Let `flow(...)` drive startup with `launch`

This is the recommendation when you want `page`, `browser`, `context`, or
`driver` injected into the callback.

On web, you can also opt into declarative launch by passing a target object with
`launch`:

```ts
import { flow } from "@qawolf/flows/web";

export default flow(
  "Open homepage",
  {
    target: "Web - Firefox",
    launch: true,
  },
  async ({ browser, context, page }) => {
    await page.goto("https://example.com");
  },
);
```

When `launch` is enabled on web, the callback receives launched browser session
objects. In tests, `launch: true` maps to the default browser launch shorthand.

### 2. Call `launch()` inside the flow

Use `launch()` when you need more explicit startup control than the common
runner-provided path.

```ts
import { flow, launch } from "@qawolf/flows/web";

export default flow("Persistent profile", "Web - Chrome", async () => {
  const { page } = await launch({
    browserContext: "persistent",
    userDataDir: "/tmp/profile",
  });
  await page.goto("https://example.com");
});
```

On web, the source code documents these defaults when `options` are omitted:

- the browser comes from the flow target
- the session starts with an incognito-style context
- GPU launch behavior comes from the flow target

`launch()` is runtime-only. The web tests verify that it throws when it is
called outside a running flow.

This is recommended for more complex use-cases. For example, when opening
multiple browser windows.

## Core Model

Think about the package in three layers.

Shared authoring model:

- `flow(...)` defines the flow
- `launch(...)` adds explicit startup control when the flow needs it

Launch-enabled runtime objects:

- web: `browser`, `context`, `page`
- Android and iOS: `driver`

Mobile-only capability:

- `device` is available on Android and iOS only
- use it for broader device or simulator control, not normal flow startup

CLI differences:

- `@qawolf/flows/cli` uses `flow(...)` only
- it does not expose `launch(...)` or `device`
- it does not inject platform runtime objects like `page` or `driver`
- it works directly with the injected base dependencies
