Tags group flows for scheduled runs and control execution order in run rules. They are primarily intended to express **run intent** rather than application structure.

Because QA Wolf supports full concurrency by default, organizing flows by feature area rarely makes sense. Instead, use tags to describe the characteristics of a run — common examples include test type (e.g., _sanity_ or _smoke_) and expected duration (e.g., _long-running_).

Before applying tags, make sure the tags you need exist. See [Workspace settings](/qawolf/Workspace-settings#tags) to create and manage tags.

## How tags are used

**Scheduling** — when creating a schedule, you can choose to run all flows or only flows with selected tags.

**Ordering** — tags can be used in run rules to control execution order. See [Ordering flows](/qawolf/Ordering-flows) for more details.
