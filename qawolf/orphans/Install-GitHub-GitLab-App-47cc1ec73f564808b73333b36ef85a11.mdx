## Setup

### Trigger Setup

<Note>
These steps require assistance from a QA Wolf representative.
</Note>

First, you will need to reach out to your QA Lead/QA Manager and get a [trigger](/qawolf/Triggers-a3348b3e92154d4a960bf5f7877ccc5d) setup to track your deployments.

Once your [trigger](/qawolf/Triggers-a3348b3e92154d4a960bf5f7877ccc5d) is setup, press the Edit “trigger name here” button to view the screen below, and click connect code hosting service

<Frame>
<img src="/images/qa-wolf-docs/image-23.png"/>
</Frame>

This will redirect you to your settings page where you can enable the GitHub or GitLab integration for your team. Click enable and then follow the process below to enable your [GitHub](/qawolf/Triggering-test-runs-on-deployment-0f12fb5260de4362a5ebe33d8a2f9538#option-2:-with-our-gh-action) or GitLab integration

<Frame>
<img src="/images/qa-wolf-docs/image-24.png"/>
</Frame>

## For GitHub

<Note>
These steps require assistance from a QA Wolf representative.
</Note>

Click the change repositories button:

<Frame>
<img src="/images/qa-wolf-docs/image-25.png"/>
</Frame>

This will open a new page that will allow you to select the repositories you would like to integrate with our application

<Frame>
<img src="/images/qa-wolf-docs/image-26.png"/>
</Frame>

Choose the repo(s) you want to test and click the green Install button. After the installation succeeds, the new tab will close.

Confirm the repo you want to test is now selected in the dropdown.

<Frame>
<img src="/images/qa-wolf-docs/image-27.png"/>
</Frame>

When you push a commit to GitHub, your tests will run after your deployment succeeds.

<Frame>
<img src="/images/qa-wolf-docs/image-28.png"/>
</Frame>

QA Wolf will comment on a pull request with the most recent test suite. As your tests run, the comment is updated to report the latest results.

<Frame>
<img src="/images/qa-wolf-docs/image-29.png"/>
</Frame>

## For GitLab

<Note>
These steps require assistance from a QA Wolf representative.
</Note>
<Warning>
GitLab integration is still experimental. We recommend contacting a QA Wolf representative before enabling it.
</Warning>

After you click the enable button next to the GitLab integration you will be met with the following screen. To integrate with our platform you will have to create a group access token with the [Maintainer role](https://docs.gitlab.com/ee/user/permissions.html#project-members-permissions) and API privileges.

<Warning>
The Maintainer Role is required because the Developer Role doesn't have enough permissions if the branch is protected, preventing us from creating pipeline checks.
</Warning>
You can follow [this tutorial](https://docs.gitlab.com/ee/user/group/settings/group_access_tokens.html) on the GitLab website to create this token. Once the token is created go ahead and paste it into the input shown below.

<Frame>
<img src="/images/qa-wolf-docs/image-30.png"/>
</Frame>

After creating your token and linking it with our platform, navigate back to your [trigger](/qawolf/Triggers-a3348b3e92154d4a960bf5f7877ccc5d), press the edit button, and select the GitLab repository that you would like this [trigger](/qawolf/Triggers-a3348b3e92154d4a960bf5f7877ccc5d) to provide PR comments and commit status updates to.

<Frame>
<img src="/images/qa-wolf-docs/image-31.png"/>
</Frame>

After you make a call to the \`deploy_success\` endpoint with the \`branch\` and \`sha\` of your merge request, you should see a comment that allows you to track the status of the suite for your merge request

<Frame caption="Merge request comment screenshot of the integration">
<img src="/images/qa-wolf-docs/image-32.png" alt='Merge request comment screenshot of the integration'/>
</Frame>


Along with the merge request comment, there will be a pipeline status created tracking whether or not your tests passed.

<Frame caption="Commit status screenshot of the integration">
<img src="/images/qa-wolf-docs/image-33.png" alt='Commit status screenshot of the integration'/>
</Frame>


## Notes on Multi-Repositories

There are two options for multi-repositories setups:

Using a GitHub/GitLab App installation per repository. This require setting up one [trigger](/qawolf/Triggers-a3348b3e92154d4a960bf5f7877ccc5d) per repository.

Leveraging a job in your CI pipeline to use our [@qawolf/ci-sdk - pollCiGreenlightStatus](/qawolf/qawolf-ci-sdk-3fc4cbe1d27f4139b1e33e9a2acd4d6a#pollcigreenlightstatus) helper, or the [CI Greenlight](/qawolf/CI-Greenlight-1b170576efea411fa785842a71e7c99e) HTTP endpoint directly.
