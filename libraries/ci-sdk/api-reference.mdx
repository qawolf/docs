`@qawolf/ci-sdk` is a TypeScript package for notifying QA Wolf of a deploy from your CI pipeline and gating the pipeline on the result. It calls the same public API the [Webhook](/deployment-testing/webhook) page documents, with typed inputs taken from the published API contract.

SDK functions do not throw. Each returns a result object with an `outcome` field, and your pipeline branches on it to decide whether the step passes or fails.

The guide for wiring it into a pipeline is [Node.js SDK](/deployment-testing/ci-sdk). This page is the function-by-function reference.

This page documents 3.6.0. `deployment.reportStatus` needs 3.1.0 or later, so a pipeline on an earlier version has only the [legacy functions](#legacy-functions) and upgrades before wiring one up. Use 3.6.0 or later for `deployment.waitForVerdict`: earlier versions fail on every call (before 3.4.1), fail while a run is still executing (before 3.5.1), or keep waiting until `timeout` on a run that needs a person (before 3.6.0).

## Installation

```bash
npm install @qawolf/ci-sdk
```

<Check>
  Requires Node.js 24.14.1 or later, below 25. The package is published as ESM only: import it with `import`, or from CommonJS with `await import("@qawolf/ci-sdk")`. `require("@qawolf/ci-sdk")` does not resolve.
</Check>

## makeQaWolfSdk

The entry point for every function. Pass your API key to initialize.

```javascript
import { makeQaWolfSdk } from "@qawolf/ci-sdk";

const { deployment } = makeQaWolfSdk({ apiKey: process.env.QAWOLF_API_KEY });
```

### Options

| Field | Type | Description |
| --- | --- | --- |
| `apiKey` | string | A QA Wolf API key, created under **Workspace Settings → API Keys**. |
| `serviceBase` | string | Base URL of the QA Wolf API. Defaults to `https://app.qawolf.com/`. |
| `userAgent` | string | `User-Agent` header sent on every request. |

A second argument injects dependencies. Each is optional:

| Field | Description |
| --- | --- |
| `fetch` | A `fetch` implementation. Defaults to the global `fetch`. Every request has a two-minute timeout. |
| `log` | A `LogDriver` from `@qawolf/ci-utils`, for routing the SDK's log lines into your CI's own logger. |
| `clock` | `{ now, sleep }`, used by `deployment.waitForVerdict`. |

Returns an object with these functions:

- **`deployment.reportStatus`** — reports a deployment. A deployment's first `success` report is what evaluates triggers and starts a run.
- **`deployment.collectDeployChanges`** — builds a deployment's `changes` from the deploy's commits, carrying ids, with secrets redacted.
- **`deployment.findLastDeployedCommit`** — reads the commit of an environment's last successful deploy.
- **`deployment.collectCommitChanges`** — builds a deployment's `changes` from the commits after a given one, without ids or redaction.
- **`codeHostIntegration.findForRepository`** — checks what QA Wolf reads of a repository.
- **`deployment.waitForVerdict`** — blocks until QA Wolf can say whether the deployment's tests passed.
- **`environment.promote`** and **`environment.terminate`** — close a preview environment, keeping or discarding its flow changes.
- **`promotion.get`** — reads how a promotion settled.
- **`uploadBuild`** — uploads an Android or iOS app build.
- **`generateSignedUrlForRunInputsExecutablesStorage`** and **`generateSignedUrlForTempTeamStorage`** — signed upload URLs for files a run needs.
- **`notifyTerminatedEphemeralEnvironment`** — deprecated; performs a promote through the legacy webhook.
- **`attemptNotifyDeploy`**, **`pollCiGreenlightStatus`** and **`makePollCiGreenlightStatusIterator`** — the [legacy functions](#legacy-functions). They report through the `deploy_success` webhook, which triggers do not see.

`detectProviderDeploymentId` is a standalone export rather than a method; see [below](#detectproviderdeploymentid).

## API keys and `workspaceId`

Every call acts on exactly one workspace.

- A **workspace API key** belongs to one workspace. `deployment.reportStatus` still requires `workspaceId`, and it has to name that workspace; naming another fails with `unauthorized`.
- An **organization API key** or a **user API key** can reach several workspaces, so `workspaceId` picks one.

Find the id under **Workspace Settings → API Keys**. The legacy functions and the signed URL functions take `workspaceId` as an optional field; see each function for what happens when it is omitted.

## deployment.reportStatus

Reports a deployment to QA Wolf through the public `deployment.reportStatus` API. The parameters are the API's own input, so [Webhook](/deployment-testing/webhook) and [Deployments](/loops/deployments) describe how each field is read.

Example:

```javascript
import { detectProviderDeploymentId, makeQaWolfSdk } from "@qawolf/ci-sdk";

const { deployment } = makeQaWolfSdk({ apiKey: process.env.QAWOLF_API_KEY });

const detected = detectProviderDeploymentId();
if (detected.outcome !== "detected") process.exit(1);

const result = await deployment.reportStatus({
  workspaceId: process.env.QAWOLF_WORKSPACE_ID,
  providerDeploymentId: detected.id,
  status: "success",
  environment: { name: "staging" },
  deployTarget: "https://staging.example.com",
  metadata: {
    commitSha: process.env.GIT_COMMIT,
    ref: process.env.GIT_BRANCH,
  },
});

if (result.outcome !== "reported") process.exit(1);
console.log(result.deployment.url);
```

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `workspaceId` | string | The workspace to report into. Required. |
| `providerDeploymentId` | string | Your identifier for the deployment. Reports carrying the same one update a single deployment. Required. See [`detectProviderDeploymentId`](#detectproviderdeploymentid). |
| `status` | `"pending"`, `"success"`, `"failure"` or `"inactive"` | The deployment's lifecycle status. Only the first `success` report evaluates triggers. Required. |
| `environment` | object | `{ id }` for an existing environment, or `{ name }`, which resolves by alias or name and creates an environment when nothing matches. Required on the first report; later reports may omit it. |
| `environment.ephemeral` | boolean | With `{ name }` only. `true` for a preview deploy. Defaults to `false`, which creates a permanent environment. |
| `environment.baseEphemeralEnvironment` | string | With `{ name }` and `ephemeral: true` only. Alias or name of the environment a created ephemeral environment copies from. |
| `deployTarget` | string | The URL the deployment serves. Required whenever the report creates an environment. |
| `environmentVariables` | object | String-to-string overrides for the runs this deployment requests. Sending it replaces the stored values; omitting it keeps them. |
| `service` | string | Which application was deployed, when several deploy into one environment. A trigger's `servicePattern` matches on it. |
| `builds` | string[] | The ids of the builds this deployment ships, at most 20, such as the `build.id` that [`uploadBuild`](#uploadbuild) returns. The runs this deployment starts install them. Omitting it keeps the stored builds. Requires 3.5.0. |
| `metadata` | object | Details about the deployed revision. Every field is optional. |
| `metadata.commitSha` | string | The deployed commit. |
| `metadata.ref` | string | The branch or ref that was deployed. |
| `metadata.repository` | string | The `owner/name` of the repository, such as `acme/web`. |
| `metadata.pullRequestNumber` | number | The pull request the deployment belongs to. Requires `metadata.repository` and a connected integration covering that repository. |
| `metadata.commitUrl` | string | A link to the commit, for when QA Wolf cannot resolve the commit itself. |
| `metadata.commitMessage` | string | The deployed commit's message. |
| `metadata.commitAuthorName` | string | The display name of the commit's author. |
| `changes` | object | What the deployment changed, for a [Smart Smoke Suite](/smart-smoke-suites) on a deploy with no pull request. Send it on the first `success` report or earlier. [`deployment.collectDeployChanges`](#deployment-collectdeploychanges) builds it; the fields and limits are under [Changes](/deployment-testing/webhook#changes). |

The input is validated strictly: a field the contract does not know, or `environment` carrying both `id` and `name`, is an `invalid-request`. `ReportDeploymentParams` is the exported type.

<Warning>
  Send `environment.ephemeral: true` for every preview deploy. A report that omits it is accepted and creates a permanent environment, one per pull request, that is never torn down.
</Warning>

### Result

Branch on `outcome`:

| `outcome` | Description |
| --- | --- |
| `"reported"` | Carries `deployment` with `id`, `status` and `url`, the environment's runs page. |
| `"invalid-request"` | The report did not satisfy the contract. Carries `message`. |
| `"unauthorized"` | The API key is unknown, or may not act on this workspace. Carries `message`. |
| `"not-found"` | The workspace or environment named in the report does not exist. Carries `message`. |
| `"conflict"` | The `providerDeploymentId` is already bound to a different environment. Carries `message`. |
| `"server-error"` | QA Wolf failed to record the report. Carries `httpStatus`. Retrying is reasonable. |
| `"unexpected-status"` | An HTTP status this SDK version does not map. Carries `httpStatus` and `message`. |
| `"network-error"` | The request never reached QA Wolf, or the connection dropped. |
| `"invalid-response-body"` | QA Wolf answered with a body the contract rejects. |

The response carries the deployment only, never the resulting runs. `deployment.waitForVerdict` is how a pipeline learns what the runs decided.

<Note>
  `outcome: "reported"` means QA Wolf recorded the deployment, not that a trigger matched it. Whether a run starts is decided afterwards, by your [triggers](/loops/overview).
</Note>

## deployment.collectDeployChanges

Builds the `changes` value for `deployment.reportStatus` from the deploy's commits in the local git history. It sends nothing itself, so you pass what it returns to `deployment.reportStatus`. Requires 3.8.0. Starting from the last deployed commit, with `environment` in place of `since`, requires 3.10.0 and `@qawolf/api-contracts` 0.155.0.

Example:

```javascript
const collected = await deployment.collectDeployChanges({
  environment: { name: "staging" },
});
if (collected.outcome !== "collected") console.warn(collected.message);

await deployment.reportStatus({
  /* ... */
  status: "success",
  changes: collected.outcome === "collected" ? collected.changes : undefined,
});
```

Each commit on the first-parent line becomes one change, with its message and changed file paths. A merge commit's message names its pull or merge request. On GitHub, a commit whose subject ends in `(#N)` is a squashed pull request, and on Azure Repos, so is a commit whose subject is `Merged PR N: <title>`. Each change carries its ids, a pull request's number and the commit it landed as, or a commit's sha, so QA Wolf lists a change it also reads from your code host only once. It never reads diffs or file contents.

Before it returns the changes, it redacts secrets from the text, such as tokens, keys, and passwords, with the same patterns QA Wolf applies when it receives them. It also removes trailers like `Co-authored-by:` that name a person by email, and leaves out any change QA Wolf wouldn't accept.

On a shallow clone, or when `since` names no commit, it returns `collected` with no changes and says what went wrong in `changes.problems`, so QA Wolf can raise a [setup problem](/smart-smoke-suites#problems-collecting-changes). The log says how to fix it.

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `since` | string | The commit or tag the environment ran before, such as the previous release tag. Without it, pass `environment`. |
| `environment` | object | `{ name }` or `{ id }`, as you pass it to `deployment.reportStatus`. Without `since`, the commits after the one QA Wolf last saw deployed there are collected. |
| `service` | string | With `environment`, which application this deploy is, as you pass it to `deployment.reportStatus`. Without it, only deploys that named no service count. |
| `repository` | object | `{ type: "url", url }` or `{ type: "full-name", fullName, host }`. Defaults to the repository your CI names, else the clone's `origin` remote. Credentials in a URL are removed before it's sent. |
| `workspaceId` | string | Only needed with an organization or user API key. |
| `pullRequests` | object | `{ token, codeHost }`. Looks up the merged pull request behind each commit with your pipeline's own token. Requires 3.9.0. See [Pull request lookup](#pull-request-lookup). |
| `include` | string[] | What each change carries: `"titles"`, `"descriptions"`, and `"paths"`. All three by default. Leaving out descriptions or paths lowers the quality of the flow selection. |
| `filter` | function | Edits the changes before they're redacted and sent. Gets the changes and returns the ones to send, and may be async. |
| `filterTimeoutMs` | number | How long `filter` may take. Defaults to 2 minutes. `Infinity` sets no limit. |
| `releaseNotes` | string | Notes written for the release, redacted and sent with the changes. |
| `cwd` | string | The repository folder. Defaults to the current directory. Pass `repository` too when it's a checkout of another repository than the one the job was started for. |
| `env` | object | The variables to read the CI's repository from. Defaults to `process.env`. |

When the filter throws, takes longer than `filterTimeoutMs`, or returns something that isn't a list of changes, none of the changes are sent, never the text as it was before the filter, and `changes.problems` says the filter failed. A returned change QA Wolf doesn't accept, such as one without a title, is left out, and `changes.problems` says the filter failed too.

### Pull request lookup

When QA Wolf doesn't read your repository's pull requests itself, `pullRequests.token` lets the SDK look up the merged pull request behind each commit, so it's sent with its number, title, description, and changed file paths. Pass `GITHUB_TOKEN` on GitHub Actions, with `pull-requests: read` permission, or `System.AccessToken` on Azure Pipelines.

- **Where the token goes.** Only to your CI's own code host: on GitHub Actions, the GitHub server the job runs for; on Azure Pipelines, the Azure Repos repository the job was started for; elsewhere, only to api.github.com for a repository on github.com. It's sent only over https, never follows a redirect, and is never sent to QA Wolf or printed. GitLab and Bitbucket aren't supported.
- **GitHub Enterprise Server on another CI.** Pass the server's API as `codeHost: { kind: "github", apiUrl: "https://github.example.com/api/v3" }`. `apiUrl` must be https and on the repository's own host.
- **Limits.** At most the 50 newest commits are looked up. A permission error, a rate limit, or a failed request stops the lookups, and the commits without a pull request are sent as commits.
- When QA Wolf reads the pull requests itself, through its GitHub or GitLab integration, nothing is looked up. Without a token, the commits are sent as they are.

### Result

Every result carries `coverage`, what QA Wolf said it reads of the repository, and `repository`, the URL it checked and where the URL came from. See [codeHostIntegration.findForRepository](#codehostintegration-findforrepository). Branch on `outcome`:

| `outcome` | Description |
| --- | --- |
| `"collected"` | Carries `changes`, ready to pass to `deployment.reportStatus`. When collecting went wrong, `changes.problems` says what. |
| `"no-starting-commit"` | Without `since`, no commit could start the range, so nothing is collected. Carries `message` and `reason`: `no-earlier-deploy` on the environment's first deploy, `not-in-history` when the clone doesn't hold that commit, `lookup-failed` when asking QA Wolf failed, or `environment-required` when neither `since` nor `environment` was given. Report the deploy without `changes`. |
| `"git-failed"` | Git failed reading the history. Carries `message`. |
| `"outdated-contracts"` | The installed `@qawolf/api-contracts` is older than 0.148.0, so it can't redact the changes, or, without `since`, older than 0.155.0. Carries `message`. |

More outcomes and reasons may be added in minor versions.

## deployment.findLastDeployedCommit

Asks QA Wolf for the commit of the environment's last successful deploy, a hint for where to start collecting changes. `deployment.collectDeployChanges` calls it for you when you pass `environment` without `since`. Requires 3.10.0 and `@qawolf/api-contracts` 0.155.0.

Example:

```javascript
const last = await deployment.findLastDeployedCommit({
  deployingCommitSha: process.env.GITHUB_SHA,
  environment: { name: "staging" },
});
if (last.outcome === "found") console.log(`Last deployed: ${last.commitSha}`);
```

The commit is a hint. QA Wolf still decides which changes count for each trigger, from the deploys that trigger already checked, so a range that starts a little early is trimmed.

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `environment` | object | `{ name }` or `{ id }`, as you pass it to `deployment.reportStatus`. Required. |
| `service` | string | Which application, when several deploy into one environment. Without it, only deploys that named no service count. |
| `repository` | string | The repository's owner/name, such as `acme/web`. Only deploys from it count: ones QA Wolf linked to it, or, when it linked none, reported with it as `metadata.repository`. |
| `deployingCommitSha` | string | The commit being deployed now. Deploys of it are skipped, so a redeploy still answers with the commit the environment ran before. |
| `workspaceId` | string | Only needed with an organization or user API key and an environment `name`. |

### Result

| `outcome` | Description |
| --- | --- |
| `"found"` | Carries `commitSha`, `deployedAt`, and `deploymentId`. |
| `"no-earlier-deploy"` | QA Wolf has no earlier successful deploy with a commit for this environment, service, and repository. A `name` no environment matches yet answers this too. Carries `message`. |
| `"outdated-contracts"` | The installed `@qawolf/api-contracts` is older than 0.155.0. Carries `message`. |

It can also return one of the usual failures, such as `not-found` for an environment id that doesn't exist. More outcomes may be added in minor versions.

## codeHostIntegration.findForRepository

Works out the job's repository and asks QA Wolf what it reads there through the workspace's code host integrations. It takes the same `repository`, `workspaceId`, `cwd`, and `env` options as `deployment.collectDeployChanges`, and never fails. Requires 3.8.0.

Example:

```javascript
const { coverage } = await codeHostIntegration.findForRepository({
  repository: { fullName: "acme/storefront", type: "full-name" },
});
if (coverage.status === "covered")
  console.log(`QA Wolf reads ${coverage.fullName} through ${coverage.provider}`);
```

`coverage.status` is one of:

| `status` | Description |
| --- | --- |
| `"covered"` | QA Wolf reads the repository. Carries `fullName`, `provider`, `permissions.code`, `permissions.pullRequests`, and `settingsUrl`. |
| `"not-covered"` | No integration covers the repository. Carries `settingsUrl`, where a workspace admin connects the code host, when QA Wolf said. |
| `"unsupported-host"` | The repository is on a code host QA Wolf doesn't connect to. |
| `"unknown"` | QA Wolf's answer couldn't be read. Carries `reason` and `message`. |

More values may be added in minor versions. Treat one you don't handle like `unknown`.

## deployment.collectCommitChanges

Builds the `changes` value for `deployment.reportStatus` from the local git history, from the commit after `since` up to `HEAD`. It returns the summary rather than sending it, so you can check or edit it first. Requires 3.7.0; earlier versions call it `collectChanges`.

Example:

```javascript
const collected = await deployment.collectCommitChanges({
  include: ["titles", "paths"],
  since: "v1.2.0",
});

if (collected.outcome === "collected") {
  await deployment.reportStatus({
    /* ... */
    status: "success",
    changes: collected.changes,
  });
}
```

Each commit on the first-parent line becomes one change. A GitHub or GitLab merge commit, or a GitHub squash-merge commit whose subject ends in `(#123)`, becomes a pull request titled from its message. Any other commit stays a commit. It reads commit messages and, when asked, changed file paths. It never reads diffs or file contents.

It reads at most the 250 newest commits. Older ones, and any left out to fit the API's limits, are counted in `omittedCount`.

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `since` | string | The commit or tag the environment ran before, such as the previous release tag. Required. |
| `include` | string[] | What each change carries: `"titles"`, `"descriptions"` or `"paths"`. Defaults to `["titles"]`. `"descriptions"` adds each message body, and `"paths"` adds the changed file paths. |
| `releaseNotes` | string | Notes written for the release, sent as they are. |
| `cwd` | string | The repository to read. Defaults to the current directory. |

### Result

Branch on `outcome`:

| `outcome` | Description |
| --- | --- |
| `"collected"` | Carries `changes`, ready to pass to `deployment.reportStatus`. |
| `"history-unavailable"` | The clone is shallow, so it may not hold the whole range. Carries `fix`. Fetch the full history, such as `fetch-depth: 0` on `actions/checkout`, or `git fetch --unshallow`. |
| `"since-not-found"` | `since` names no commit in this repository, such as a typo or a tag that wasn't fetched. Carries `fix`. |
| `"git-failed"` | Git failed for another reason. Carries `message`. |

## detectProviderDeploymentId

Composes a `providerDeploymentId` from the variables your CI system already sets. The id is distinct for every job definition and every re-run, so a retried job or a second job deploying alongside the first gets its own deployment rather than reporting into one whose first `success` already evaluated triggers.

Example:

```javascript
import { detectProviderDeploymentId } from "@qawolf/ci-sdk";

const detected = detectProviderDeploymentId();
if (detected.outcome !== "detected") process.exit(1);
// detected.ci is "jenkins", detected.id is the value of BUILD_TAG
```

| CI system | Detected on | Id |
| --- | --- | --- |
| GitHub Actions | `GITHUB_ACTIONS` | `GITHUB_RUN_ID`-`GITHUB_RUN_ATTEMPT`-`GITHUB_JOB` |
| GitLab CI | `GITLAB_CI` | `CI_PIPELINE_ID`-`CI_JOB_ID` |
| CircleCI | `CIRCLECI` | `CIRCLE_WORKFLOW_ID`-`CIRCLE_BUILD_NUM` |
| Buildkite | `BUILDKITE` | `BUILDKITE_BUILD_ID`-`BUILDKITE_JOB_ID`-`BUILDKITE_RETRY_COUNT` |
| Jenkins | `JENKINS_URL` or `JENKINS_HOME` | `BUILD_TAG` |
| Bitbucket Pipelines | `BITBUCKET_WORKSPACE` or `BITBUCKET_BUILD_NUMBER` | `BITBUCKET_BUILD_NUMBER`-`BITBUCKET_STEP_UUID`-`BITBUCKET_STEP_RUN_NUMBER` |

### Options

| Field | Type | Description |
| --- | --- | --- |
| `discriminator` | string | Appended to the id after a colon. Required when one job definition deploys more than once at a time: a GitHub Actions or Jenkins `matrix`, a Jenkins `parallel` block, a CircleCI job with `parallelism`, or a loop over environments. Pass the value that tells the deployments apart. |
| `env` | object | The variables to read. Defaults to `process.env`. |

### Result

| `outcome` | Description |
| --- | --- |
| `"detected"` | Carries `ci` and `id`. |
| `"missing-variables"` | The CI system was recognized but a variable it composes the id from is unset. Carries `ci` and `missingVariables`. |
| `"unsupported"` | No recognized CI system. Compose the id from your own CI's variables instead. |

The helper is optional. `providerDeploymentId` is always required on the report, and any value that changes on every re-run and differs between concurrent deploys works.

## deployment.waitForVerdict

Blocks until QA Wolf can say whether a deployment's tests passed. Give it the `deployment.id` the report returned; resolving that to the runs the triggers created, and those runs to a status, happens inside.

On GitHub Actions, `qawolf/wait-for-verdict-action` runs this wait as a workflow step. See [GitHub Actions](/deployment-testing/github-actions).

Example:

```javascript
const report = await deployment.reportStatus({ /* ... */ status: "success" });
if (report.outcome !== "reported") process.exit(1);

const verdict = await deployment.waitForVerdict({
  deploymentId: report.deployment.id,
  timeout: 45 * 60 * 1000,
});

process.exit(["passed", "not-tested"].includes(verdict.outcome) ? 0 : 1);
```

<Warning>
  Set `timeout` below your CI job's own time limit. When the job's limit fires first, the job is killed with no run link and no explanation. When `timeout` fires first, the result is `timed-out` with the stage, the elapsed time and every run URL the wait knew about.
</Warning>

### Options

Every field except `deploymentId` is optional. Durations are in milliseconds.

| Field | Default | Description |
| --- | --- | --- |
| `deploymentId` | — | The `deployment.id` from `deployment.reportStatus`. Required. |
| `timeout` | 2 hours | Whole-operation budget. |
| `runAppearanceTimeout` | 5 minutes | Gives up if no trigger has produced a run by then. Runs that did appear are still waited on. |
| `triggerPollInterval` | 3 seconds | Between polls while a trigger is still producing a run. |
| `runPollInterval` | 30 seconds | Between polls while a run executes. |
| `maxRetries` | 10 | Network and server-error retries before giving up. |
| `retryInterval` | 10 seconds | Between those retries. |
| `onProgress` | — | Called on every stage change with a `VerdictStage`, for your build log. |
| `signal` | — | An `AbortSignal`. Aborting it yields `canceled-by-caller`. |

The stages `onProgress` receives, in order:

- **`waiting-for-evaluation`** — QA Wolf has not yet evaluated the deployment's triggers.
- **`waiting-for-run`** — triggers matched and at least one is still creating a run. Carries `matchedTriggerCount`.
- **`waiting-for-verdict`** — every run is known and at least one is still executing. Carries `runs`.

### Result

Branch on `outcome`:

| `outcome` | Description |
| --- | --- |
| `"passed"` | Every run QA Wolf started passed. Carries `runs`. |
| `"failed"` | A run failed, or found a bug that is still open and serious enough to block. Carries `runs` and `blockingBugCount`. |
| `"not-tested"` | Nothing tested this deployment. Carries `reason` and `triggers`, one note per trigger saying why. |
| `"run-canceled"` | A run was canceled, so there is no verdict. Not a pass. Carries `runs`. |
| `"superseded"` | A newer deployment to the same branch and environment replaced the run before it finished, so there is no verdict for this deployment. Not a pass. Carries `runs` and `supersededBy` with the replacement's `runId` and `url`. |
| `"needs-review"` | Every run finished, and its failures wait for a person on the run page. There is no verdict yet. Not a pass. Carries `runs`, where such a run reads `running`. |
| `"timed-out"` | The budget ran out. Carries `elapsedMs`, `lastStage` and the `runs` it had already found. |
| `"canceled-by-caller"` | The `signal` was aborted. |
| `"unauthorized"` | The API key is unknown, or may not read this deployment. Carries `message`. |
| `"not-found"` | No such deployment. Carries `message`. |
| `"server-error"` | QA Wolf kept failing after every retry. Carries `httpStatus`. |
| `"unexpected-status"` | An HTTP status this SDK version does not map. Carries `httpStatus` and `message`. |
| `"network-error"` | The connection never came back within the retries. |
| `"invalid-response-body"` | QA Wolf answered with a body the contract rejects. |

`not-tested` is a separate answer from `passed`. A deployment no trigger matched was not tested, which is a different fact from tests passing, and your pipeline decides what it is worth. `reason` is `"no-trigger-matched"` when every trigger was evaluated and none matched, or `"no-run-created"` when a trigger matched and something stopped it from creating a run; each entry in `triggers` then carries `triggerName`, a `message` for the log and, for `no-run-created`, a stable `reason` code to branch on.

`needs-review` means a person must answer before QA Wolf can decide: QA Wolf does not call a run passed or failed while a failure still waits for a diagnosis. The wait returns as soon as only a person can move the run, either because QA Wolf asked a question about each failure without a diagnosis or because the workspace does not investigate runs. Each run's `runUrl` takes your build log to the run page, where someone answers the questions. After that the run settles to `passed` or `failed`. The example above exits `1` on it.

`superseded` is what a cancel-in-progress pipeline looks like from the older job: the newer deployment's job carries the verdict. Reserve a distinct exit code for it when your CI should treat the job as skipped rather than failed.

Each entry in `runs`:

| Field | Description |
| --- | --- |
| `runId` | The run's id. |
| `runUrl` | Absolute URL of the run page. |
| `status` | `"queued"`, `"running"`, `"passed"`, `"failed"`, `"canceled"` or `"superseded"`. Terminal on every outcome except `timed-out` and `needs-review`, where a run waiting for a person reads `"running"`. |
| `blockingBugCount` | Open bugs serious enough to block the build. |
| `supersededBy` | The replacing run's `runId` and `url`. Present only when `status` is `"superseded"`. |
| `triggerName` | The trigger that created the run. |

`DeploymentVerdict`, `VerdictRun`, `VerdictStage`, `TriggerNote` and `NotTestedReason` are the exported types. The same shape is published as `deploymentVerdictSchema` in `@qawolf/api-contracts`.

## environment.promote and environment.terminate

Close a preview environment that `deployment.reportStatus` created, once its pull request is done. The two are not interchangeable:

- **`environment.promote`** — the work was accepted, typically on merge. The environment's flow changes are merged into its base environment, and the environment is terminated once they land.
- **`environment.terminate`** — the work was abandoned, typically on a close without merge. The flow changes are discarded and the environment's runs are canceled.

Terminating an accepted preview throws away the flow work done for that pull request. Promoting an abandoned one merges flows nobody kept into the base environment that every later preview copies from.

With a connected GitHub or GitLab integration, QA Wolf hears about the pull request closing from the code host, and neither call is needed.

Example:

```javascript
const { environment } = makeQaWolfSdk({ apiKey: process.env.QAWOLF_API_KEY });

if (pullRequestWasMerged) {
  const result = await environment.promote({
    environmentId: `preview/pr-${pullRequestNumber}`,
    workspaceId: process.env.QAWOLF_WORKSPACE_ID,
  });
  if (result.outcome !== "requested") process.exit(1);
  console.log(result.promotion.id, result.promotion.status); // "pending"
} else {
  const result = await environment.terminate({
    environmentId: `preview/pr-${pullRequestNumber}`,
    workspaceId: process.env.QAWOLF_WORKSPACE_ID,
  });
  if (result.outcome !== "terminated") process.exit(1);
}
```

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `environmentId` | string | The environment's id or one of its aliases. Required. |
| `workspaceId` | string | Required to look up an alias with an organization or user API key. A workspace API key implies it. |

### Result

`environment.promote` answers `"requested"` with `promotion`, in `pending`, because the merge runs in the background; read how it settled with `promotion.get`, below. `environment.terminate` answers `"terminated"` with `environment`, whose `terminatedAt` is set. Both share these refusals:

| `outcome` | Description |
| --- | --- |
| `"invalid-request"` | The environment is already terminated, a promoted environment has no base environment to merge into, or an alias was sent without the `workspaceId` an organization or user key needs. Carries `message`. |
| `"unauthorized"` | The API key is unknown, or may not act on this workspace. Carries `message`. |
| `"not-found"` | No environment matches `environmentId`. Carries `message`. |
| `"conflict"` | The call clashes with the environment's current state. Carries `message`. |
| `"server-error"` | QA Wolf failed to answer. Carries `httpStatus`. Retrying is reasonable. |
| `"unexpected-status"` | An HTTP status this SDK version does not map. Carries `httpStatus` and `message`. |
| `"network-error"` | The request never reached QA Wolf, or the connection dropped. |
| `"invalid-response-body"` | QA Wolf answered with a body the contract rejects. |

Calling `environment.promote` again while a promotion is open returns that same promotion rather than opening a second one. An environment whose promotion is still being applied cannot be terminated until it settles; one whose promotion is `conflicted` can.

## promotion.get

Reads how a promotion that `environment.promote` requested settled.

Example:

```javascript
const { promotion } = makeQaWolfSdk({ apiKey: process.env.QAWOLF_API_KEY });

const result = await promotion.get({ promotionId });
if (result.outcome !== "found") process.exit(1);
console.log(result.promotion.status);
```

`promotion.status` is one of:

- **`pending`** and **`resolving`** — not settled yet. Poll again.
- **`promoted`** — the flow changes landed in the base environment. Carries `promotedCommitHash`.
- **`no-changes`** — there was nothing to merge.
- **`conflicted`** — the flow changes clash with the base environment. `conflict.paths` names the files. A person resolves it in QA Wolf, and the environment stays until they do.
- **`abandoned`** — the environment was terminated before the promotion settled.

`conflict` is present while the status is `conflicted` or `resolving`, and `settledAt` once it is `promoted`, `no-changes` or `abandoned`. Refusals are the same as for `environment.promote`, with `not-found` meaning no promotion matches `promotionId`.

A promotion usually settles within a minute or two. The SDK has no wait helper for it, so a pipeline that needs the settled status polls `promotion.get` while it reads `pending` or `resolving`.

## uploadBuild

Uploads an Android `.apk` or `.aab`, or an iOS `.ipa`, of up to 1 GB, and registers it as a QA Wolf build. QA Wolf reads the app id, version and build number from the file. The file is streamed from disk, so a large build is not held in memory.

Example:

```javascript
const { uploadBuild } = makeQaWolfSdk({ apiKey: process.env.QAWOLF_API_KEY });

const result = await uploadBuild({
  filePath: "app/build/outputs/apk/release/app-release.apk",
  environment: { name: "staging" },
  branch: process.env.GIT_BRANCH,
  commitSha: process.env.GIT_COMMIT,
  workspaceId: process.env.QAWOLF_WORKSPACE_ID,
});

if (result.outcome !== "uploaded") process.exit(1);
console.log(result.build.id, result.build.appId, result.build.version);
```

### Parameters

| Field | Type | Description |
| --- | --- | --- |
| `filePath` | string | Path to the build file. Required. |
| `environment` | object | The environment whose runs install this build from now on, until a newer build of the same app and platform arrives. `{ id }`, or `{ name }` with the same `ephemeral` and `baseEphemeralEnvironment` options as `deployment.reportStatus`, which creates the environment when nothing matches. Omit it for a build that only the runs created with it install. |
| `branch` | string | Shown with the build. |
| `commitSha` | string | Shown with the build. |
| `workspaceId` | string | Required with an organization or user API key. |

### Result

`"uploaded"` carries `build` with `id`, `appId`, `appName`, `platform`, `version`, `buildNumber`, `fileName`, `sizeBytes` and `url`. Otherwise:

| `outcome` | Description |
| --- | --- |
| `"file-unreadable"` | `filePath` does not name a readable file. Nothing was sent. Carries `filePath`. |
| `"upload-rejected"` | Storage refused the file, for example because the upload URL expired. Carries `buildId` and `httpStatus`. |
| `"upload-network-error"` | The file never reached storage, or the connection dropped. Carries `buildId`. |
| `"invalid-request"`, `"unauthorized"`, `"not-found"`, `"conflict"`, `"server-error"`, `"unexpected-status"`, `"network-error"`, `"invalid-response-body"` | QA Wolf refused or failed one of its two calls, with the same meanings as for `deployment.reportStatus`. `failedStep` says which: `"request-upload"`, where `invalid-request` means the file is not an `.apk`, `.aab` or `.ipa` or is over 1 GB, or `"create"`, where `invalid-request` means the file is not an app and also carries `buildId`. |

A failed call creates no build. Each call uploads the file as a new build, so retrying is calling `uploadBuild` again.

To start runs that install the build, pass `result.build.id` to `deployment.reportStatus` as `builds`. See [Upload builds](/upload-builds).

## notifyTerminatedEphemeralEnvironment

<Warning>
  Deprecated since 3.4.0. Despite its name, this function performs a promote: the legacy `environment_terminated` webhook merges the environment's flow changes into its base and then terminates it. Use `environment.promote`, above, for accepted work and `environment.terminate` to discard abandoned work, which this function has never done. It keeps working, prints no warning and has no removal date.
</Warning>

Tells QA Wolf that an ephemeral environment has been terminated. QA Wolf stops the runs targeting it and promotes any flow changes to the base environment. See [webhooks/environment\_terminated](/environment_terminated) for the underlying endpoint.

With a connected GitHub or GitLab integration, QA Wolf hears about the pull request closing from the code host, and this call is redundant.

Example:

```javascript
const { notifyTerminatedEphemeralEnvironment } = makeQaWolfSdk({
  apiKey: process.env.QAWOLF_API_KEY,
});

const result = await notifyTerminatedEphemeralEnvironment({
  environmentAlias: "preview/pr-42",
  workspaceId: process.env.QAWOLF_WORKSPACE_ID,
});

if (result.outcome !== "success") process.exit(1);
```

### Input fields

Pass exactly one of the following to identify the environment:

| Field | Type | Description |
| --- | --- | --- |
| `environmentId` | string | Id of the ephemeral environment. |
| `environmentAlias` | string | Alias of the ephemeral environment. |
| `deploymentUrl` | string | The URL the environment was created with. |

`environmentAlias` and `deploymentUrl` also take `workspaceId`. It is optional; an organization or user key that omits it acts on the organization's first-created workspace, and the result carries a `warning` naming it. `NotifyTerminatedEphemeralEnvironmentInput` is the exported type.

### Result fields

| Field | Description |
| --- | --- |
| `outcome` | `"success"` or `"aborted"`. |
| `environmentId` | Id of the terminated environment. Present on `"success"`. |
| `abortReason` | Present on `"aborted"`: `"401-unauthorized"`, `"403-forbidden"`, `"409-conflict"`, `"4XX-client-error"`, `"5XX-server-error"` or `"network-error"`. |
| `httpStatus` | HTTP status code on an HTTP abort. |

## generateSignedUrlForRunInputsExecutablesStorage

<Warning>
  Deprecated for Android and iOS builds. Use [`uploadBuild`](#uploadbuild) instead, so every run records which build it tested. It keeps working, prints no warning, and is still the way to upload Windows app files. A zipped app that is not an `.ipa` also stays on this path for now.
</Warning>

Generates a signed URL for uploading a run input executable (APK, AAB, DEB, IPA, ZIP, CSV, PDF) to QA Wolf. See [v0/run-inputs-executables-signed-urls](/run-inputs-executables-signed-urls) for the underlying endpoint, and [Legacy build uploads](/legacy-build-uploads) for the pipeline it belongs to. To upload an Android or iOS build, use [`uploadBuild`](#uploadbuild).

Example:

```javascript
import fs from "fs/promises";

const { generateSignedUrlForRunInputsExecutablesStorage } = makeQaWolfSdk({
  apiKey: process.env.QAWOLF_API_KEY,
});

const signed = await generateSignedUrlForRunInputsExecutablesStorage({
  destinationFilePath: "app-staging.apk",
  workspaceId: process.env.QAWOLF_WORKSPACE_ID,
});

if (!signed.success || !signed.uploadUrl || !signed.interactiveRunFileLocation) {
  throw new Error("No upload URL received from QA Wolf");
}

await fetch(signed.uploadUrl, {
  method: "PUT",
  body: await fs.readFile("./path/to/build.apk"),
  headers: { "Content-Type": "application/octet-stream" },
});
```

### Input fields

| Field | Type | Description |
| --- | --- | --- |
| `destinationFilePath` | string | Filename and extension, optionally including directories. You choose it; your flows resolve the build by the same name. See [Legacy build uploads](/legacy-build-uploads). |
| `workspaceId` | string | Required with an organization or user API key. Without it the request fails. |

### Response fields

| Field | Description |
| --- | --- |
| `success` | `true` when the signed URL was generated. |
| `uploadUrl` | Pre-signed URL for uploading the file with `PUT`. |
| `interactiveRunFileLocation` | File path without the workspace id. Pass it to the run as an environment variable. |
| `playgroundFileLocation` | Deprecated alias of `interactiveRunFileLocation`. Removed in a future major version. |
| `abortReason` | Present on `success: false`: `"400-invalid-request"`, `"401-invalid-credentials"`, `"403-forbidden"`, `"5XX-server-error"`, `"XXX-other-http-code"`, `"client-network-error"` or `"sdk-argument-validation-failed"`. |

<Note>
  A failed request from this function reports `abortReason: "client-network-error"` and `httpStatus: 0` whatever the real status was. The SDK logs the real status on the line above, so read the log rather than branching on `abortReason`. A `400` from an organization or user key most often means `workspaceId` was not sent.
</Note>

`generateSignedUrlForTempTeamStorage` takes the same input and returns the same fields, for files that are not executables.

## Legacy functions

<Warning>
  `attemptNotifyDeploy` and `pollCiGreenlightStatus` report through the legacy `deploy_success` webhook, which feeds [legacy triggers](/legacy-triggers/overview) only. A [trigger](/loops/overview) never sees a deployment they send. They were deprecated in 3.1.0 and are still exported in 3.6.0: legacy describes the path they report through, not an old version of the package. They keep working unchanged, print no warning, and have no removal date. A new integration uses `deployment.reportStatus` and `deployment.waitForVerdict`.
</Warning>

Moving a pipeline off them: `deploymentType` becomes `environment.name`; `branch` and `sha` move into `metadata`; `providerDeploymentId` is new and required, and subsumes `deduplicationKey`; `hostingService` disappears, since the code host comes from your integration; `variables` becomes `environmentVariables`. There is no `skipped` outcome, because whether a trigger matched is not known at report time; `deployment.waitForVerdict` answers `not-tested` instead.

### attemptNotifyDeploy

Notifies QA Wolf of a successful deployment through [webhooks/deploy\_success](/deploy-success).

Example:

```javascript
const { attemptNotifyDeploy } = makeQaWolfSdk({
  apiKey: process.env.QAWOLF_API_KEY,
});

const result = await attemptNotifyDeploy({
  branch: process.env.GIT_BRANCH,
  sha: process.env.GIT_COMMIT,
  deploymentType: "staging",
  hostingService: "GitHub",
  repository: { name: "web", owner: "acme" },
  commitUrl: undefined,
  deduplicationKey: undefined,
  deploymentUrl: undefined,
  pullRequestNumber: undefined,
  variables: undefined,
});

if (result.outcome === "skipped") process.exit(0);
if (result.outcome !== "success") process.exit(1);
const runId = result.runId;
```

#### DeployConfig fields

`DeployConfig` is a union of `GitHubDeployConfig`, `GitLabDeployConfig` and `EphemeralDeployConfig`. Every field is declared on the type, so pass `undefined` for the ones you do not use.

| Field | Type | Description |
| --- | --- | --- |
| `branch` | string | VCS branch name. |
| `sha` | string | VCS commit SHA. |
| `deploymentType` | string | The label the legacy trigger matches on. |
| `deploymentUrl` | string | Overrides the environment URL. Available in flows as `process.env.URL`. |
| `hostingService` | `"GitHub"` or `"GitLab"` | Where your code is hosted. Decides the shape of `repository`. |
| `commitUrl` | string | Makes the commit a clickable link in the QA Wolf UI when no repository is configured. |
| `pullRequestNumber` | number | GitHub pull request number, for PR testing. |
| `mergeRequestNumber` | number | GitLab merge request number, for MR testing. |
| `repository` | object | `{ name, owner }` for GitHub, `{ name, namespace }` for GitLab. |
| `ephemeralEnvironment` | `true` | With `deploymentUrl`, for a preview without a code host integration. |
| `deduplicationKey` | string | Custom key controlling run cancellation. |
| `variables` | object | Environment variable overrides for the triggered runs. |
| `workspaceId` | string | Optional. An organization or user key that omits it acts on the organization's first-created workspace, and the result carries a `warning` naming it. |

#### Result fields

| Field | Description |
| --- | --- |
| `outcome` | `"success"`, `"skipped"`, `"failed"` or `"aborted"`. |
| `runId` | Id of the created run. Present on `"success"`; `undefined` for a preview deployment. |
| `environmentId` | The environment the deployment resolved to. Present on `"success"`. |
| `skippedDeployment` | Present on `"skipped"`: no trigger matched. Carries the server's `reason` and `message` when sent. |
| `failReason` | Present on `"failed"`: `"no-environment"`, `"run-could-not-be-created"`, `"trigger-skipped"` or `"unknown-result"`. |
| `skippedTriggers` | Present with `failReason: "trigger-skipped"`: the triggers that matched but could not run, each with `reason` and `message`. |
| `abortReason` | Present on `"aborted"`: `"401-unauthorized"`, `"403-forbidden"`, `"4XX-client-error"`, `"5XX-server-error"`, `"network-error"` or `"invalid-response-body"`. |
| `httpStatus` | HTTP status code on an HTTP abort. |

### pollCiGreenlightStatus

Polls [v0/ci-greenlight](/v0-ci-greenlight) for a run id until the run completes. The run id comes from `attemptNotifyDeploy`, so this function only works for pipelines on the legacy path.

Example:

```javascript
const { pollCiGreenlightStatus } = makeQaWolfSdk({
  apiKey: process.env.QAWOLF_API_KEY,
});

const { outcome } = await pollCiGreenlightStatus({
  runId,
  onRunStageChanged: (current, previous) => {
    console.log(current.runStage, previous?.runStage);
  },
});

if (outcome !== "success") process.exit(1);
```

#### Options

| Field | Default | Description |
| --- | --- | --- |
| `runId` | — | The run id returned by `attemptNotifyDeploy`. Required. |
| `onRunStageChanged` | — | Called with the current and previous `CiGreenlightStatus` when the run stage changes. |
| `pollTimeout` | 2 hours | Milliseconds before the poll aborts with `"poll-timed-out"`. |
| `abortOnSuperseded` | `false` | When `true`, aborts with `"superseded-run"` when a newer run supersedes this one. |
| `runInProgressInterval` | 30 seconds | Between polls while the run is in progress. |
| `runUnderReviewInterval` | 60 seconds | Between polls while the run is under review. |
| `maxRetries` | 10 | Network retries before aborting. |
| `retryInterval` | 10 seconds | Between those retries. |

#### Result fields

| Field | Description |
| --- | --- |
| `outcome` | `"success"`, `"failed"` or `"aborted"`. Only `"failed"` means blocking bugs were found. |
| `greenlightStatus` | The final `CiGreenlightStatus`. Present on `"success"` and `"failed"`. |
| `abortReason` | Present on `"aborted"`: `"poll-timed-out"`, `"run-canceled"`, `"superseded-run"`, `"network-error"`, `"404-run-not-found"`, `"4XX-client-error"`, `"5XX-server-error"` or `"XXX-other-http-code"`. |
| `httpStatus` | HTTP status code on an HTTP abort. |

### makePollCiGreenlightStatusIterator

An async generator over the same poll, for a pipeline that needs to stop early on its own criteria. Takes the same options as `pollCiGreenlightStatus` except `onRunStageChanged`.

Example:

```javascript expandable
const { makePollCiGreenlightStatusIterator } = makeQaWolfSdk({
  apiKey: process.env.QAWOLF_API_KEY,
});

for await (const iteration of makePollCiGreenlightStatusIterator({ runId })) {
  if (iteration.isAborted) {
    console.error(`Poll aborted: ${iteration.abortReason}`);
    process.exit(1);
  }

  const { status } = iteration;
  switch (status.runStage) {
    case "initializing":
    case "underReview":
      break;
    case "completed":
      if (!status.greenlight) process.exit(1);
      process.exit(0);
    case "canceled":
      process.exit(1);
    default:
      status.runStage satisfies never;
      throw new Error(`Unexpected run stage: ${status.runStage}`);
  }
}
```

Each iteration is either a status update or an abort:

| Field | Present when | Description |
| --- | --- | --- |
| `isAborted` | always | `false` for a status update, `true` for an abort. |
| `elapsedMs` | always | Milliseconds since polling started. |
| `status` | `isAborted: false` | The current `CiGreenlightStatus`. |
| `previousStatus` | `isAborted: false` | The status from the previous iteration. `undefined` on the first. |
| `stageChanged` | `isAborted: false` | `true` when the run stage changed since the previous iteration. |
| `isFailedTerminalStage` | `isAborted: false` | `true` when the run completed without a greenlight or was canceled. |
| `abortReason` | `isAborted: true` | Why polling stopped. The iterator never aborts with `"superseded-run"`. |
| `httpStatus` | `isAborted: true` | HTTP status code on an HTTP abort, otherwise `undefined`. |
| `message`, `reason` | `abortReason: "run-canceled"` | QA Wolf's explanation of the cancellation, when sent. `reason` is an open set of codes. |

<Warning>
  Handle every run stage in the `switch`. The `default: status.runStage satisfies never` arm makes TypeScript error when a stage is added and the code does not handle it, instead of silently passing the job.
</Warning>

## Versioning

The package follows SemVer.

- Depend on it with the `^` range operator. Patch and minor releases do not introduce breaking changes.
- A major version bump marks a breaking change, announced in advance.
- Only top-level exports are covered. New fields in response types, and changes to log output, are not breaking changes.

Minimum versions for the functions on this page:

| Function | Since |
| --- | --- |
| `deployment.reportStatus`, `detectProviderDeploymentId` | 3.1.0 |
| `deployment.waitForVerdict` | 3.2.0, and 3.5.1 for a wait that completes |
| `deployment.waitForVerdict` answering `superseded` | 3.3.0 |
| `environment.promote`, `environment.terminate`, `promotion.get` | 3.4.0 |
| `uploadBuild` | 3.5.0 |
| `deployment.waitForVerdict` answering `needs-review` | 3.6.0 |

The changelog is in the package's README on [npm](https://www.npmjs.com/package/@qawolf/ci-sdk).
