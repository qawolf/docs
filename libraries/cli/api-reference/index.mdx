Use this section for stable command descriptions, flags, configuration, environment variables, and exit codes.

## Commands

- [`qawolf auth`](/libraries/cli/api-reference/commands#auth) — manage authentication.
- [`qawolf flows`](/libraries/cli/api-reference/commands#flows) — run, list, and pull flows.
- [`qawolf install`](/libraries/cli/api-reference/commands#install) — install runtime dependencies for the project.
- [`qawolf init`](/libraries/cli/api-reference/commands#init) — scaffold a project in the current directory.
- [`qawolf doctor`](/libraries/cli/api-reference/commands#doctor) — diagnose problems running flows locally.
- [`qawolf runner`](/libraries/cli/api-reference/commands#runner) — launch and drive a QA Wolf-hosted browser, Android device, or iOS device.
- [`qawolf agent`](/libraries/cli/api-reference/commands#agent) — ask the QA Wolf AI for work and follow what it does.
- [`qawolf run`](/libraries/cli/api-reference/commands#run) — trigger and manage QA Wolf runs on the platform.
- [`qawolf attempt`](/libraries/cli/api-reference/commands#attempt) — investigate a finished run attempt.
- [`qawolf build`](/libraries/cli/api-reference/commands#build) — upload app builds.
- [`qawolf help`](/libraries/cli/api-reference/commands#help) — display help for a command, or print the whole CLI's help as Markdown.
- [Public API commands](/libraries/cli/api-reference/commands#public-api-commands) — one command for each QA Wolf public API operation.

Example invocation:

```bash
qawolf auth login
qawolf flows pull --env <env_id>
qawolf flows run
```

Find the environment ID in the app URL — see [Pull flows](/local-execution/run-flows-locally#pull-an-environment).

## Global options

The following flags apply to every command:

- `--verbose` — emits debug logs to stderr.
- `--json` — formats output as JSON.
- `--agent` — formats output for agent consumption.
- `-V, --version` — prints the CLI version.

When the CLI detects a recognized CI environment (`CI`, `GITHUB_ACTIONS`, `GITLAB_CI`, `CIRCLECI`, `JENKINS_URL`, `BUILDKITE`), output defaults to JSON. When it detects a recognized agent environment (`CLAUDE_CODE`, `CURSOR_SESSION_ID`), output defaults to agent mode.

With `--json` or `--agent`, the CLI writes the structured result to stdout and diagnostic text to stderr, so scripts can parse stdout directly.

## Exit codes

Every qawolf CLI command exits with one of the codes below.

| Code | Name | Meaning |
| --- | --- | --- |
| `0` | `success` | The command completed successfully. |
| `1` | `testFailure` | One or more flows failed, a `qawolf runner run --follow` run did not pass, or a runner action did not take effect. |
| `2` | `invalidArgs` | A Commander parse error, an unknown subcommand, a bad flag value, or a runner asked for something it can't do, such as a screenshot of an Android or iOS runner before its first run. |
| `3` | `auth` | `QAWOLF_API_KEY` is missing or invalid. |
| `4` | `network` | The QA Wolf API was unreachable, a download from storage failed, a registry was unreachable, or a runner could not serve the request yet. |
| `5` | `config` | `qawolf.config.ts` is invalid, or a file collision occurred during `qawolf init`. |
| `6` | `timeout` | A command exceeded its timeout. |
| `7` | `payment` | The workspace's billing state prevented the command. |
| `8` | `notFound` | The command named a runner, run, or other resource that does not exist. A runner with that id was never launched, was terminated, or timed out from inactivity. |
