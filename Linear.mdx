## What this integration does

- **Automatic issue handling.** Creates Linear issues automatically when new bug reports are generated in QA Wolf.
- **Synchronization.** Closing a bug report in QA Wolf closes the linked Linear issue, and closing, reopening, or updating the Linear issue updates QA Wolf.
- **Test creation requests.** Add a **QA Wolf** label to a Linear issue, or assign it to a QA Wolf user, to automatically create a coverage request in QA Wolf. Matching ignores case and accepts `qawolf` or `qa wolf`.
- **The QA Wolf agent.** Mention QA Wolf in an issue comment, or delegate an issue to it, and the [agent](/agent-in-your-tools) works on it and replies in the issue.

## Requirements

- Access to a QA Wolf workspace
- A Linear team to create issues in
- A Linear workspace admin to approve the QA Wolf app

## How to connect QA Wolf to Linear

<Steps>
  <Step title="Start the connection">
    Open **Workspace settings → Integrations**. Under **Issue tracking**, select **Connect** on the **Linear** card. Connecting Linear also adds the QA Wolf agent to your Linear workspace.
  </Step>

  <Step title="Configure the integration">
    Enter the **Team name** exactly as it appears in Linear. The team name is case sensitive.

    Enable **Create bug report issue**. Optionally set **Label UUID** and **Assignee UUID** to give newly created issues a default label and assignee.
  </Step>
</Steps>

If the Linear card shows **Linear is connected, but QA Wolf couldn't finish setting up the agent**, select **Retry setup**.

## Work with the agent in Linear

Start a session from any issue in a Linear team the QA Wolf app can access:

- **Mention it** — in a comment, type `@`, choose **QA Wolf**, and say what you need.
- **Delegate the issue** — assign the issue to **QA Wolf**. With no comment, the agent reads the issue and acts on it, and asks if the request isn't clear.

The agent posts **QA Wolf is working on this.** while it starts, then replies in the session. Reply in the same session to continue. When a reply comes down to a few choices, the agent offers options you select.

Each session starts with the issue's title, description, status, labels and earlier comments. It doesn't see attachments. Guidance you write for agents in Linear applies too, unless it conflicts with QA Wolf's own instructions.

A new mention or delegation opens a new session. It rereads the issue and its comments, but not earlier sessions.

### Choose which Linear teams it works in

The agent works in the Linear teams the QA Wolf app can access. To add or remove a team, change the app's team access in Linear. QA Wolf picks up the change automatically.

One Linear workspace answers to one QA Wolf workspace. If your organization has several QA Wolf workspaces, the agent answers for the one that connected Linear most recently.

## If the agent doesn't answer

A session that stays pending with no reply means QA Wolf doesn't recognize the Linear workspace. Check that Linear reads **Connected** under **Workspace settings → Integrations**. If your workspace connected Linear before the agent was available, disconnect Linear and connect it again.

When the agent can't help, it replies with the reason:

- **"QA Wolf isn't available for this Linear team."** Give the QA Wolf app access to the issue's team in Linear, then try again.
- **"…its QA Wolf team doesn't have a default environment."** Set a default environment for your QA Wolf workspace, then mention the agent again.
- **"…I can't determine which QA Wolf user should own this conversation."** Create a [trigger](/triggers/overview) on your default environment, then mention the agent again.
- **"QA Wolf reviewed this but didn't produce a response."** Reply in the session with what you'd like the agent to do.
