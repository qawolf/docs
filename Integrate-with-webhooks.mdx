If QA Wolf has no native integration for your bug tracker, a webhook connects it instead. QA Wolf posts to an endpoint you host when a bug report opens or closes, and your endpoint answers with the issue it created.

## Requirements

- Access to a QA Wolf workspace
- An endpoint that accepts `POST` requests and returns JSON

## How to connect a webhook

<Steps>
  <Step title="Start the connection">
    In QA Wolf, go to **Workspace settings → Integrations**, click **Enable** next to **Webhook**, then click **Connect**.
  </Step>

  <Step title="Define the webhook">
    Give the webhook a title, then enter the webhook URL — the location your bug tracker listens on.

    <Frame>
      ![](/images/integrate-your-issue-tracker/image-27.png)
    </Frame>
  </Step>

  <Step title="Choose which events to send">
    Enable **Notify when bug report is opened** and **Notify when bug report is closed**.

    <Frame>
      ![](/images/integrate-your-issue-tracker/image-28.png)
    </Frame>
  </Step>
</Steps>

## Authentication

If a username and password are set, QA Wolf uses them for basic HTTP authorization on every `POST` to your webhook.

## When a bug report opens

Your endpoint receives a `POST` with a JSON body (`Content-Type: application/json`).

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique bug report ID. |
| `title` | string | Bug report title. |
| `description` | string | Detailed description. May contain newlines and links. |
| `url` | string | Link to view the bug report in QA Wolf. |
| `event` | string | `bug-report-opened`. |

Example:

```json
{
  "id": "<QAWOLF_BUG_REPORT_ID>",
  "title": "Bug Report Title",
  "description": "🐞\n\nBug report description:\nYou can see it here.\n\nBug report:\nhttps://app.qawolf.com/test-client/bug-reports/...\n\nAffected workflows:\n\n\nIf you are aware of this bug you can set the priority to low which will prevent it from causing a run failure.",
  "url": "https://app.qawolf.com/bug-reports/...",
  "event": "bug-report-opened"
}
```

### What your endpoint returns

Respond with a payload carrying these fields.

| Field | Type | Description |
| --- | --- | --- |
| `externalId` | string | ID of the issue in your bug tracker. QA Wolf uses it to identify issues to update later. |
| `humanId` | string | Human-friendly issue ID, shown in the QA Wolf UI, Slack messages, and other integrations. |
| `url` | string | Link to the issue. |

## When a bug report closes

Your endpoint receives a `POST` with a JSON body (`Content-Type: application/json`).

| Field | Type | Description |
| --- | --- | --- |
| `externalId` | string | ID of the issue associated with the closed bug report. |
| `event` | string | `bug-report-closed`. |
