A short procedure for a developer or a coding agent. A coding agent can read this page as plain Markdown at [docs.qawolf.com/onboard.md](https://docs.qawolf.com/onboard.md), and the full documentation index at [docs.qawolf.com/llms.txt](https://docs.qawolf.com/llms.txt).

## Requirements

- A QA Wolf workspace, which your workspace administrator can invite you to
- A QA Wolf API key — **Workspace Settings → Integrations → API Access**
- Node.js 20.19 or later, if you install the CLI with npm

## How to set up the CLI

<Steps>
  <Step title="Install the CLI">
    ```bash
    npm install -g @qawolf/cli
    ```

    If you'd rather not install Node.js, download a standalone binary from [GitHub Releases](https://github.com/qawolf/cli/releases). Confirm the CLI is on your `PATH`:

    ```bash
    qawolf --version
    ```
  </Step>

  <Step title="Connect to your workspace">
    Sign in through a browser or with an API key:

    ```bash
    qawolf auth login
    ```

    In CI or an agent sandbox, set `QAWOLF_API_KEY` instead. A team API key is the whole credential — nothing needs a browser login or a held connection.

    ```bash
    export QAWOLF_API_KEY=<your-api-key>
    ```

    Confirm the connection:

    ```bash
    qawolf auth whoami
    ```

    Read more: [Authenticate the QA Wolf CLI](/local-execution/authenticate).
  </Step>

  <Step title="Choose an environment">
    List your environments and pick the id or alias you want to work in:

    ```bash
    qawolf --json environment find
    ```

    Set `QAWOLF_ENVIRONMENT` to reuse it, or pass it explicitly to the commands below.

    Read more: [Pull an environment](/local-execution/pull-flows#pull-an-environment).
  </Step>

  <Step title="Pull flows and install the runtime">
    ```bash
    qawolf flows pull --env <env>
    qawolf install
    ```

    Flows land in the `.qawolf/<env>/` cache. `qawolf install` adds the browsers and other runtime dependencies those flows need.

    Read more: [Install runtime dependencies](/local-execution/install-dependencies).
  </Step>

  <Step title="Run flows locally">
    ```bash
    qawolf flows list
    qawolf flows run --env <env>
    ```

    The CLI exits `0` when every flow passes and `1` when one or more fail. See [exit codes](/libraries/cli/api-reference/index#exit-codes) for the rest.

    Read more: [Run flows locally](/local-execution/run-flows-locally).
  </Step>

  <Step title="Start a run on the platform">
    To run on QA Wolf infrastructure rather than your machine:

    ```bash
    qawolf run create --environment-id <env> --flow-ids <flow_id>
    ```

    Select flows by id, by `--tag`, or both.

    Read more: [CLI command reference](/libraries/cli/api-reference/commands).
  </Step>
</Steps>

<Note>
  Commands target `https://app.qawolf.com` by default. Set `QAWOLF_HOST_URL` to reach another deployment.
</Note>

## If a step fails

```bash
qawolf doctor
```

It reports the CLI version, the Node.js version, credentials, connectivity to QA Wolf, and the installed browsers.

Read more: [Diagnose problems](/local-execution/diagnose-problems).

## For coding agents

The CLI ships a `qawolf-cli` agent skill covering every command, its read or write kind, and the conventions that matter — pass `--json` for stable output, and terminate interactive runners, which bill while they run. Agents such as Claude Code, Codex, Cursor, and Gemini CLI can use it. It's included in the [`@qawolf/cli` package](https://github.com/qawolf/cli) under `skills/qawolf-cli`.

<Tip>
  Before using a command whose flags you don't know, run `qawolf <command> --help`. The installed CLI always matches its own version.
</Tip>
