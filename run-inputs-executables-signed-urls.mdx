`GET https://app.qawolf.com/api/v0/run-inputs-executables-signed-urls`

<Warning>
  Deprecated for Android and iOS builds. Upload them as [builds](/upload-builds) instead, so every run records which build it tested. See [Move from legacy uploads](/upload-builds#move-from-legacy-uploads). This endpoint keeps working, and it is still the way to upload Windows and Linux app files. A zipped app that is not an `.ipa` also stays on this path for now.
</Warning>

For Windows and Linux app files from Node.js, use [`@qawolf/ci-sdk`](/libraries/ci-sdk/api-reference) instead of calling this endpoint directly.

This endpoint accepts app builds only: `.aab`, `.apk`, `.appimage`, `.deb`, `.exe`, `.ipa`, `.msi`, `.rpm`, and `.zip`. A file your flows read, such as a `.csv` or `.pdf`, returns a `400`. Upload it to [team storage](/use-files-in-flows#upload-a-file) instead.

<Steps>
  <Step title="Generate a signed URL">
    ```bash
    curl "https://app.qawolf.com/api/v0/run-inputs-executables-signed-urls?file=$DESTINATION_FILE_PATH" \
      -H "Authorization: Bearer $QAWOLF_API_KEY"
    ```

    Returns a `signedUrl` for the next step, plus `fileLocation` and `interactiveRunFileLocation` — see below for the full parameter and response reference.
  </Step>
  <Step title="Upload the file">
    `PUT {signedUrl}`

    The previous request returns the signed URL. It is not a fixed `/api/` endpoint — it points directly to Google Cloud Storage.

    ```bash
    curl -X PUT \
      --header "Content-Type: application/octet-stream" \
      --data-binary @some_file.zip \
      $SIGNED_URL
    ```
  </Step>
</Steps>

## Query parameters

| Parameter | Description |
| --- | --- |
| `file` | Destination file path. At minimum the filename and extension. May include directories. |
| `workspaceId` | Workspace to upload to. Required with an organization or user API key. Ignored by a workspace API key, which already implies its workspace. See [which workspace a request acts on](/rest-overview#which-workspace-a-request-acts-on). |

## Response

```json
{
  "fileLocation": "$WORKSPACE_ID/$DESTINATION_FILE_PATH",
  "interactiveRunFileLocation": "$DESTINATION_FILE_PATH",
  "playgroundFileLocation": "$DESTINATION_FILE_PATH",
  "signedUrl": "https://..."
}
```

| Field | Description |
| --- | --- |
| `fileLocation` | Full path including the workspace id. Use this to reference the file in run configurations. |
| `interactiveRunFileLocation` | Path without the workspace id. Pass it to the run as an environment variable, and use it to reference the file in an interactive run. |
| `playgroundFileLocation` | Deprecated alias of `interactiveRunFileLocation`. Removed in a future major version. |
| `signedUrl` | Pre-signed URL for uploading the file. Use in the next step. |

## Response codes

| Code | Description |
| --- | --- |
| `200` | Success. |
| `400` | `file` is missing, or its extension isn't one this endpoint accepts. Also returned when an organization or user API key omits `workspaceId`. |

Plus the [common response codes](/rest-overview#common-response-codes).
