A failed `expect` stops the flow, so no check after it runs. A failed `expect.soft` records the failure, and the flow keeps going. After the last line, the attempt fails and lists every failed check. QA Wolf investigates each failed check on its own, so failures with different causes can lead to separate bugs.

```ts
expect.soft(subject, name)
```

- `subject` — what to check, the same as for `expect`
- `name` — optional label that QA Wolf records with the failure

Example:

```ts
import { expect, flow } from "@qawolf/flows/web";

export default flow(
  "Review an invoice",
  { target: "Web - Chrome", launch: true },
  async ({ page }) => {
    await page.goto(`${process.env.BASE_URL}/invoices/42`);

    await expect.soft(page.getByRole("heading"), "Invoice heading").toHaveText("Invoices");
    await expect.soft(page.getByTestId("invoice-total"), "Invoice total").toHaveText("$120.00");

    const pay = page.getByRole("button", { name: "Pay" });
    await expect(pay).toBeEnabled();
    await pay.click();
    await expect(page.getByText("Paid")).toBeVisible();
  },
);
```

If the heading and the total are both wrong, the flow records both failures and still checks the Pay button. If the Pay button is also disabled, the flow stops there, and the attempt reports all three failures.

## When to use soft checks

- Use `expect.soft` for checks that nothing later in the flow depends on, such as several values on one page.
- Use `expect` for a check that a later step relies on, such as a button the flow clicks next.
- Don't use `expect.soft` inside a loop. Each iteration that fails records its own failure.

## Name each check

Pass a short name as the second argument, such as `"Invoice total"`. QA Wolf records the name with the failure, so a reader can tell failures apart without opening the flow's code.

## Platforms and limits

- **Platforms** — web, iOS, Android and Windows flows. Use the `expect` you already import from `@qawolf/flows`. In Windows flows, `expect.soft` dispatches on its subject the same way `expect` does.
- **Call only** — `expect.soft(...)` takes a subject and a name. `expect.soft.poll` and `expect.soft.configure` aren't available.
